# Product Scope

## 제품 한 문장

교사가 교수·학습 및 평가 정보를 한 번 입력하면 학교가 설정한 평가계획 양식에 맞춰 검증·취합·출력할 수 있게 하는 웹 기반 업무 시스템.

## 핵심 사용자 가치

- 평가계 담당자는 학교의 문서 구조와 공통 규칙을 한 번 설정한다.
- 교사는 HWP 표 서식을 직접 맞추지 않고 내용 데이터만 입력한다.
- 학사일정은 교수·학습표의 주차 생성과 일정 맥락에 재사용한다.
- 시스템은 평가 구조 오류를 자동 검증한다.
- 동일 데이터로 학교용/공개용 등 여러 출력물을 생성할 수 있다.

## 핵심 업무 흐름

```text
평가계 담당자
  학사일정 설정
  + 학교 Evaluation Template 설정
          ↓
교사
  Template 기반 데이터 입력
  + 자동 검증
          ↓
평가계 담당자
  취합/검토/승인
          ↓
결정론적 Document Renderer
  PDF 등 결과물 생성
```

## 사용자 역할

### SCHOOL_ADMIN
학교 시스템 관리자.

- 관리자 계정과 역할 관리
- 평가관리자 지정
- 학교 기본 설정

평가업무 내용 전체를 관리하는 역할과 계정/권한 관리 역할을 분리한다.

### EVALUATION_ADMIN
부장, 평가계 등 평가업무 관리자.

- 학사일정 설정/검토
- 일반 교사 계정 발급/비밀번호 초기화
- 학교 평가계획 Template 설정
- 문서 Section/순서 설정
- 교수·학습표 열 구성 설정
- 평가 공통 정책 설정
- 평가계획 작성 현황 확인
- 제출 계획 검토/반려/승인
- 전 교과 자료 출력

### TEACHER
일반 교사.

- 본인에게 배정된 학년/교과 평가계획 작성
- 학교 Template에 의해 생성된 데이터필드 입력
- 교수·학습표 작성
- 지필/수행평가 입력
- 수행평가 세부기준 작성
- 검증
- 제출
- 반려된 계획 수정

## Template 생성 방식

평가계 담당자는 다음 두 방식을 모두 사용할 수 있다.

1. 작년도 평가계획 PDF를 업로드하고 AI가 Section/표 구조를 Template Schema 초안으로 제안
2. 빈 Template에서 직접 Section/열을 구성

AI 결과는 반드시 수정 가능해야 하며 자동 확정하지 않는다.

## 개인정보/표시 원칙

시제품은 공개 웹에서 실행하는 것을 가정한다.
교사 표시명은 기본적으로 `김OO (영어)` 형태를 사용한다.
내부 식별자는 UUID/Auth UID 등 별도 고유 ID를 사용한다.

공개용 문서 생성 시 교사명은 기본적으로 제외할 수 있도록 출력 정책을 분리한다.

## 제품 원칙

- 동일 정보는 한 번만 입력한다.
- 교사는 문서 서식을 직접 맞추지 않는다.
- 학교별 문서 차이는 Template 계층에서 처리한다.
- Template은 교사 입력 Schema와 출력 Layout을 연결한다.
- 정기고사/공휴일/학교행사 등 학교 공통정보는 중앙 학사일정을 참조한다.
- 일반 교사 화면은 작성에 필요한 기능만 보여준다.
- AI는 제안/분석에 사용하고 업무 사실을 무검토 확정하지 않는다.
- 최종 PDF 생성에는 AI를 사용하지 않는다.

## 확장 가능해야 하는 기능

- 전교과 평가요약표
- 교육계획서용 출력
- 학부모 공개용 출력
- HWPX/Excel 출력 검토
- NEIS Export Adapter
- 수행평가 일정 집중도 분석
- AI 내용 검토
