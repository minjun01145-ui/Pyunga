# Phase 2 Checklist — 수행평가 입력기 프로토타입

## 목표

수행평가 세부기준을 HWP 자유표 대신 구조화 데이터로 표현할 수 있는지 실제 UI에서 검증한다.

이번 단계에서는 Firebase 저장, 인증, PDF, AI를 구현하지 않는다.

## 구현된 범위

- 수행평가명
- 반영비율
- 수행평가 총점
- 영역별 평가 / 전체 단일기준 전환
- 영역 추가/삭제
- 영역별 배점
- 4개 구조화 ScoringModel 편집기
  - 수준별 배점
  - 횟수·기록별 배점
  - 조건 충족 개수별 배점
  - 세부항목 합산
- Domain validation
- 검증 메시지
- 개발 확인용 구조 데이터(JSON) 보기
- ScoringModel 관련 테스트 확대

## 의도적으로 구현하지 않은 범위

- custom_table 실제 편집기
- Firebase 저장
- 로그인
- 성취기준 연결
- 평가시기
- PDF 출력
- AI 검수

## 확인 방법

1. `npm install`
2. `npm run check`
3. `npm run build`
4. `npm run dev`
5. `/teacher/performance-prototype` 접속

## 직접 확인할 시나리오

### 시나리오 A — 일반적인 30/30/40

- 내용 30
- 표현 30
- 전달력 40
- 합계 100
- 오류 없음 확인

### 시나리오 B — 영역 합계 오류

- 전달력을 35로 변경
- 영역 합계 95 오류 확인

### 시나리오 C — 체육형

- 전체 단일기준으로 변경
- 횟수·기록별 배점 선택
- 자유투 10개 100, 9개 90 등을 작성

### 시나리오 D — 조건 충족형

- 영역 평가
- 조건 충족 개수별 배점 선택
- 조건을 추가/삭제하고 충족 개수 규칙 검증

### 시나리오 E — 세부항목 합산형

- 영역 배점 30
- 세부항목 최고점을 10 + 10으로 설정
- 합계 불일치 오류 확인
- 15 + 15로 변경 후 오류 해소 확인

## Phase 2 종료 판단

다음 질문에 "예"라고 답할 수 있으면 Phase 3으로 이동한다.

1. 실제 학교 수행평가의 주요 유형을 이 구조로 자연스럽게 작성할 수 있는가?
2. 새로운 평가유형이 생겨도 별도 ScoringModel을 추가할 수 있는 구조인가?
3. UI 코드가 Domain validation을 대신하지 않는가?
4. 특정 교과를 위한 하드코딩이 없는가?
5. 사용자 정의 표가 필요한 예외 사례를 구분할 수 있는가?
